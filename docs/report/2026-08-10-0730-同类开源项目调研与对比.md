# hiPhone 同类开源项目调研与对比

日期: 2026-08-10 07:30
调研方式: Web 搜索 + GitHub 仓库页实地抓取
数据时效: 星标数/活跃度为 2026-08-10 当日快照

---

## 0. 核心结论

hiPhone 不属于任何一个现成品类，它**同时踩在三个独立开源生态的交叉点上**：

```
        浏览器内 OS 外壳                    AI 角色扮演前端
     (daedalOS / Puter / Win11React)   (SillyTavern / RisuAI / Agnai)
                    ╲                        ╱
                     ╲                      ╱
                      ╲   ★ hiPhone 在这里 ╱
                       ╲                  ╱
                        ╲                ╱
                    浏览器内 App 运行时 / AI 造 App
                       (Puter SDK / bolt.diy)
```

三条关键发现：

1. **"高保真移动 OS 外壳"这一格在开源界基本是空的。** 浏览器内 OS 项目清一色是**桌面** OS（Windows/macOS/Linux 风格）；`awesome-web-desktops` 收录的 60+ 个项目里**没有一个是移动 OS**。找得到的 iOS 网页复刻全是玩具级（`iphone-in-react` 2 ⭐ / 14 commits，`react-iphone` 停更）。hiPhone 的 13.2k 行 Shell 层——Springboard 拖拽分页、AppSwitcher 卡片物理、投影式手势阈值、Dynamic Island、Liquid Glass 材质——**在开源世界没有对手**。

2. **"AI 角色扮演"这一格极度拥挤，而且 hiPhone 是唯一不兼容事实标准的那个。** SillyTavern（31.9k ⭐）定义了 Character Card V2/V3 + World Info 规范，RisuAI、Agnai、OMate、LettuceAI、Pyre、OpenCharaAgent **全部兼容**它的角色卡。hiPhone 有自己的 `characterStore` / `worldBookStore`，**与整个生态不互通**——这是当前最大的战略孤立点，也是最容易补的一块。

3. **hiPhone 的真正差异化不是"和 AI 聊天"，而是"角色活在一台被模拟的手机里"。** 所有竞品的范式都是**消息列表 + 角色卡**；hiPhone 是**角色有朋友圈、会写备忘录、心跳 agent 在你不看时自己生活、你还能切视角进对方的手机**。这个方向上唯一在做类似事情的是 `OpenCharaAgent`（4 ⭐，Python，角色有独立 workspace 和调度器），成熟度远低于 hiPhone。

## 1. 赛道 A：浏览器内 OS 外壳

| 项目 | ⭐ | 许可证 | 技术栈 | 定位 | 与 hiPhone 的关系 |
|------|-----|--------|--------|------|------------------|
| [**Puter**](https://github.com/HeyPuter/puter) | 43k | AGPL-3.0 | JS/Node + Rust | "Internet OS"，自托管，云盘/DB/AI/Workers + App Store | **架构上最像的对手**（见赛道 C） |
| [**daedalOS**](https://github.com/DustinBrett/daedalOS) | 13k | MIT | Next.js + React + Framer Motion + react-rnd | 浏览器桌面环境，BrowserFS + IndexedDB | 同为"OS 保真度"路线，但目标是桌面 |
| [**Win11React**](https://win11.blueedge.me) | — | — | React | Windows 11 网页复刻 | 纯外观复刻，无应用生态 |
| [**macOS-web**](https://macos-web.app) | — | — | Svelte | macOS 网页复刻 | 同上 |
| [**AnuraOS / OS.js / AaronOS / EmuOS**](https://github.com/syxanash/awesome-web-desktops) | — | 各异 | 各异 | 桌面 OS 框架 / 复古模拟 | 同上 |
| [iphone-in-react](https://github.com/ike-gg/iphone-in-react) | **2** | — | Next.js + Redux + TS | iOS 主屏 + 开关 App 动画 | **唯一找到的 iOS 网页复刻，14 commits，无测试** |

### 逐项分析

**daedalOS** 是这条赛道上工程质量最高的对手，值得学两点：

- **文件系统抽象**：用 BrowserFS 把 IndexedDB 包装成 POSIX 风格 FS，所有 app 通过统一 FS 接口读写。hiPhone 现在是 39 个 store 各自持久化，**没有统一的"文件"概念**——这也是为什么 `dataPortability` 得直接遍历 object store。
- **第三方 app 策略完全相反**：daedalOS 通过**模拟器**（BoxedWine 跑 Win32、js-dos 跑 DOS、v86 跑 x86 镜像、Ruffle 跑 Flash）运行**已有的历史软件**；hiPhone 是**编译执行新写的 TSX**。daedalOS 的路线拿到了"海量现成内容"，hiPhone 的路线拿到了"原生一致的 UI 体验"。

**Puter** 43k ⭐ 是这个领域的头部，但它是**云端 OS**（需要后端、账号、自托管 Docker），hiPhone 是**纯前端本地优先**（IndexedDB，零后端，Cloudflare Pages 静态托管）。两者的用户承诺完全不同：Puter 卖"你的云电脑"，hiPhone 卖"你口袋里的另一个世界"。

**关键结论**：hiPhone 在移动 OS 保真度上是开源世界的**独一份**。这不是"还没人做"，而是**做这件事的成本极高**——iOS 手势物理、材质分层、动画时序需要 13k 行和数百次调参（项目 237 篇 plan 里有大量就是在调这个）。这是真实护城河。

## 2. 赛道 B：AI 角色扮演前端

| 项目 | ⭐ | 许可证 | 技术栈 | 角色卡 | 记忆机制 | 移动端 |
|------|-----|--------|--------|--------|----------|--------|
| [**SillyTavern**](https://github.com/SillyTavern/SillyTavern) | **31.9k** | AGPL-3.0 | Node.js + JS | **V2/V3 事实标准** | World Info + 手动摘要 + 扩展 | 弱（网页自适应） |
| [**RisuAI**](https://github.com/kwaroran/RisuAI) | 1.6k | GPL-3.0 | Svelte + TS + Tauri + Capacitor | 兼容 ST | **HypaMemory V2/V3 压缩** + SupaMemory | 强（Capacitor 原生） |
| [**Agnai**](https://github.com/agnaistic/agnai) | — | AGPL-3.0 | TS | 兼容 ST | Lorebook + 摘要 | 中 |
| [**OpenCharaAgent**](https://github.com/OpenChara/OpenCharaAgent) | 4 | Apache-2.0 | Python + Node | 兼容 ST V1/V2/V3 | 角色独立 workspace + 持久记忆 | 网页可用 |
| [**LettuceAI**](https://github.com/LettuceAI/app) | — | — | 跨平台原生 | 自有 | 长期记忆 | 强（Android 原生） |
| [**Pyre**](https://github.com/devemberteam-ops/pyre) | — | AGPL-3.0 | 跨平台 | 自有 | 本地优先 | 强 |
| [**OMate**](https://omate.org/) | 闭源 | 商业 | iOS/Android | **导入 ST 角色卡+世界书+预设+聊天记录** | 长期记忆 + 面具(身份) | 原生 App |
| **hiPhone** | — | **无 LICENSE** | React 19 + Zustand + Vite | **自有格式，不兼容** | 三 pass 压缩流水线 + memoryState | PWA |

### 关键对比维度

**(a) 角色卡生态 —— hiPhone 唯一的短板，也是最大的机会**

Character Card V2/V3 是这个领域的 HTTP 协议。Chub、JanitorAI 等站点有**数十万张现成角色卡**，附带头像、开场白、示例对话、世界书。所有竞品都能一键导入。

hiPhone 的 `characterStore` + `worldBookStore` 是自研格式。这意味着新用户进来面对的是**空白的角色列表**，而竞品用户进来面对的是**几十万张卡任选**。

值得注意的是 **OMate 的定位几乎就是 hiPhone 的商业版**：BYOK、本地存储、面具（多身份）、长期记忆——而它把"**兼容 SillyTavern 角色卡·世界书·预设**"直接写进了官网 slogan。这说明在这个品类里，**兼容 ST 生态是被市场验证过的必选项，不是加分项**。

**(b) 记忆机制 —— hiPhone 处于第一梯队**

hiPhone 的三 pass 压缩流水线（`compressionPassA/B/C` + `compressionPipeline`）+ 结构化 `memoryState` + 确定性 `memoryEvents` 事实流水，工程完成度对标 RisuAI 的 HypaMemory V2/V3，**优于** SillyTavern 的"World Info + 手动摘要 + 扩展拼凑"。

hiPhone 独有的一条：`ai/CLAUDE.md` 里那套围绕**厂商 KV cache 命中率**设计的四段式 prompt 分层规则（稳定内容进 System、app 协议进中段、高频变化进 Post-history）。这是成本/延迟层面的优化，在竞品文档里**没见到同等深度的论述**。

**(c) 主动性 —— hiPhone 与 OpenCharaAgent 并列领先**

绝大多数竞品是**纯被动**的：你不发消息，角色不存在。

hiPhone 的心跳系统（30s tick、Web Worker 规避后台节流、ReAct 工具循环、虚拟世界经历生成、AI-AI 对话引擎）让角色在你不看时继续生活并产生记忆。唯一做类似事情的 OpenCharaAgent 让角色作为"long-lived process"持续运行、拥有独立 workspace——但它是 Python 后端 + OS 级沙箱，4 ⭐，属于早期实验。

**(d) 交互范式 —— hiPhone 的真正差异化**

| | 竞品范式 | hiPhone 范式 |
|--|---------|-------------|
| 载体 | 消息列表 / Visual Novel 立绘 | **一整台模拟手机** |
| 角色表达 | 文字 + 表情立绘 + TTS | 文字 + 表情包 + **朋友圈动态** + **个性签名** + **备忘录** |
| 世界 | 纯文本 lorebook | 天气、地图、音乐、日历、照片构成的**可交互环境** |
| 视角 | 单一（我和角色） | **可切换到角色的手机看 TA 的数据**（`EntityStoreRegistry` 多实体隔离） |
| 扩展 | 插件改 UI/prompt | **在手机里装新 App**（Sucrase 沙箱 + `@hiphone/*` SDK） |

"切视角进对方手机"这个玩法，在调研到的所有开源项目里**独一无二**。

## 3. 赛道 C：浏览器内 App 运行时 / AI 造 App

| 项目 | ⭐ | 隔离方式 | 编译 | SDK | 分发 |
|------|-----|---------|------|-----|------|
| [**Puter**](https://github.com/HeyPuter/puter) | 43k | iframe + postMessage | 无（就是网页） | `puter.js`（Apache-2.0）：AI / 存储 / KV / Workers | 官方 App Store，可变现 |
| [**bolt.diy**](https://github.com/stackblitz-labs/bolt.diy) | — | **WebContainer**（浏览器内完整 Node）| 真 npm + Vite/Next | 无（就是完整 Node 生态） | 导出/部署 |
| [**OpenCharaAgent**](https://github.com/OpenChara/OpenCharaAgent) | 4 | OS 级沙箱（sandbox-exec / bubblewrap+Landlock） | terminal 工具 | 文件系统 | 角色自产内容 |
| **hiPhone** | — | **L1 软沙箱**（`new Function` + 遮蔽 10 个全局） | **Sucrase**（TSX→CJS，带 sourcemap） | `@hiphone/*` 12 个模块白名单 | 内置 App Store（ZIP 上传）+ AI 工坊生成 |

### 分析

**hiPhone 的方案是"轻量但真实"的中间路线**：不像 bolt.diy 那样扛整个 Node（WebContainer 体积巨大且**商用需要 StackBlitz 授权**），也不像 Puter 那样"app 就是一个普通网页"（失去原生 UI 一致性）。Sucrase 编译 TSX + SDK 白名单，让第三方 App **长得和内置 App 一模一样**——这是 hiPhone 的正确取舍。

**但隔离强度是三者里最弱的**。对比：

- Puter：iframe + postMessage，**真实边界**
- OpenCharaAgent：OS 级沙箱 + 全量工具调用审计日志
- hiPhone：`new Function` 参数遮蔽，`userApp/CLAUDE.md` 自己写明"**不是对抗性安全边界，逃逸路径存在**"

在"用户只跑自己写的 app"时无所谓；一旦 App Store 出现**用户之间分享 ZIP**，一个恶意 app 就能读走全部聊天记录、角色记忆和**明文存储的 API Key**。Puter 的 iframe 方案是现成的升级路径参考，而 hiPhone 的 `ModuleResolver` 已按"可跨 iframe 序列化"预留了接口。

**AI 造 App 的对比**：bolt.diy 的 agent 能装依赖、跑 dev server、读控制台报错并自修；hiPhone 的 AI 工坊有 9 个工具（读写删文件 / 列文件 / 编译检查 / 计划更新 / finish），`compile_check` 是唯一的验证手段。差距在**反馈回路的深度**——bolt.diy 能看到运行时错误，hiPhone 只能看到编译错误。这是 AI 工坊后续最值得补的能力（把 ErrorBoundary 捕获的运行时异常喂回 agent）。

## 4. 赛道 D：直接同品类（"小手机"）

这是 hiPhone 真正的产品品类。调研结果：

| 项目 | 开源 | 状态 |
|------|------|------|
| **小手机**（国内 App） | ❌ 闭源商业 | 品类命名者 |
| [**OMate**](https://omate.org/) | ❌ 闭源商业 | iOS/Android 原生；BYOK；**兼容 ST 角色卡/世界书/预设/聊天记录**；面具多身份；本地存储 |
| [LINUX DO 上的个人 Next.js 项目](https://linux.do/t/topic/836061) | 部分开源 | 明确自述灵感来自"小手机、omate"；已实现文字/贴纸/AI 图片描述/红包、单聊群聊 prompt 框架、记忆管理 + 群聊记忆链接、WorldBook 注入；剧情衔接与记忆系统仍在完善 |
| **hiPhone** | 🔶 **无 LICENSE / 无 README / `private: true`** | 功能覆盖面最广（16 个 App + 心跳 + 视角切换 + App 运行时） |

**结论**：这个品类在开源侧**几乎是真空**。唯一的开源同类是个人早期项目，功能面远窄于 hiPhone（无 OS 外壳、无 App 生态、无心跳、无视角切换）。而商业侧的 OMate 已经验证了这个品类的市场，并把"兼容 ST 生态"当作核心卖点。

**hiPhone 现在的状态是"事实上未开源"**——仓库里没有 LICENSE、没有 README、`package.json` 标着 `private: true`。任何人看到这个仓库都无法合法使用它（无许可证 = 默认保留全部权利）。

## 6. 战略建议

### 6.1 立刻做：接入 SillyTavern 角色卡生态（最高 ROI）

实现 Character Card **V2/V3 导入**（JSON + PNG 内嵌 tEXt chunk）+ World Info 导入，映射到现有 `characterStore` / `worldBookStore`。

- **成本**：一个解析器 + 一次字段映射，估计 3-5 天
- **收益**：新用户从"空白角色列表"变成"数十万张现成角色卡任选"，冷启动问题一次性解决
- **风险**：低——只做导入不做导出，不影响现有数据结构
- **佐证**：RisuAI / Agnai / LettuceAI / OpenCharaAgent / OMate **全部这么做了**，这是这个品类的入场券

### 6.2 定位：不要在"AI 聊天"上和 SillyTavern 正面竞争

SillyTavern 有 31.9k ⭐、300+ 贡献者、11700+ commit 和不可撼动的扩展生态。hiPhone 一个人无法在"prompt 可调性/扩展丰富度"上追上。

正确打法是**把 SillyTavern 当上游生态吸收（导入角色卡），把竞争维度换到它不做的地方**：

1. **OS 外壳保真度** — 开源界无对手，且门槛极高
2. **世界模拟** — 朋友圈/备忘录/音乐/天气构成的可交互环境
3. **角色主动性** — 心跳 agent 让角色在你不看时活着
4. **多视角** — 切进角色的手机看 TA 的数据
5. **App 运行时** — 用户/AI 能给这台手机装新功能

这五条里**每一条 SillyTavern 都不做**，而它们组合起来就是"小手机"这个品类的定义。

### 6.3 开源前必须补的三件事

当前仓库**无 LICENSE、无 README、`private: true`**——处于"公开可见但法律上不可用"的状态。若打算开源：

1. **选许可证**。同行参考：SillyTavern / Puter / Pyre 用 **AGPL-3.0**（防止闭源商业套壳，考虑到 OMate 这类商业竞品的存在，AGPL 是这个品类的主流选择），RisuAI 用 GPL-3.0，daedalOS 用 MIT。
2. **写 README**。当前项目的能力对外**完全不可见**——16 个 App、心跳 agent、App SDK、多视角，从仓库首页一个字都看不到。
3. **法务出清**（详见体检报告 P2-4）：苹果原版图标 + iOS 原版壁纸 + "hiPhone" 命名。**开源会显著放大这个风险**——闭源自用是低概率事件，公开仓库 + 公网部署 + 明确对标 iPhone 是另一回事。

### 6.4 中期：向 Puter 学沙箱，向 bolt.diy 学反馈回路

- **沙箱**：L1 → iframe + postMessage（Puter 的现成范式），配套 app 权限声明（storage / ai / network）。触发条件是"用户之间开始分享 app 包"。
- **AI 工坊**：把运行时错误（`UserAppErrorBoundary` 已经在捕获了）喂回 agent 循环，从"只有编译检查"升级到"能看到 app 跑起来炸在哪"——这是 bolt.diy 相对成熟的地方。

### 6.5 可选：从 daedalOS 借鉴统一文件系统抽象

39 个 store 各自持久化的结构，长期会让"App 之间共享数据""统一备份粒度""per-app 存储配额"都变难。daedalOS 用 BrowserFS 把 IndexedDB 包成 FS 接口，值得作为 H3 阶段的参考——但这属于大手术，优先级低于前面几条。
